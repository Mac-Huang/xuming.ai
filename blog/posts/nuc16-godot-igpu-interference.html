Sharing an iGPU:
graphics and local AI

Goal: Can an app’s state and frame timing help us run local AI faster while keeping graphics responsive?

One Godot scene + one local language model, sharing the same integrated GPU.

01Unnecessary redraws cost real inference time

Animated graphics made each new token take 4.8× as long. Even an unchanged scene slowed inference if it kept redrawing. Pausing redraws in that unchanged scene brought token time back to baseline.

Average time per new token · lower is better

No graphics app15.3 ms
Unchanged scene, still redrawing49.2 ms
Animated lights72.8 ms
Lower 3D resolution22.3 ms
Unchanged scene, redraw paused15.2 ms

Pausing is appropriate only while the view is unchanged; animation and interaction still need new frames.

02The average gap is not a safe time budget

At 60 FPS, a frame has 16.67 ms. Static rendering took 12.58 ms at the median; the opaque pass alone took 10.20 ms.

4.09 ms

But the slower end of the distribution reached 19.97 ms (95th percentile)—already beyond the frame budget. The 4.09 ms remainder is not guaranteed inference time; display composition and other work still need room.

03Switching between applications adds a cost

In a separate small-kernel test, alternating two GPU processes added 31.7 µs per dispatch cycle: about 12.6 µs more between kernels and 19.2 µs more inside their elapsed spans.

This includes CPU and runtime effects. Pure GPU context-switch overhead was not isolated.

The measured graphics + inference timeline

What this suggests: use app state to avoid unnecessary redraws. For active graphics, schedule bounded inference work using conservative frame-cost estimates. We measured the opportunity; a scheduler that guarantees frame deadlines is still future work.
How we measured it—and what remains unknown

NUC16/Core Ultra 7 356H; Godot 4.5 Vulkan; Qwen2.5-0.5B FP16 with OpenVINO 2026.0. Each request used 1,024 input tokens and generated 64 tokens. Token time averages the 63 decode steps after the first token.

The table uses 50 requests without the full pass profiler: five randomized blocks, two requests per state per block. A separate 50-request campaign captured 45 graphics markers. All 100 outputs matched. The calibrated diagnostic recorded 46,016 inference kernels; two handoff experiments recorded 120,000 dispatches in total.

Cross-process dispatch-cost increase: 31.71 µs, with a paired-block bootstrap 95% interval of 23.64–40.35 µs. This is cooperative handoff after completion, not forced preemption. Frame percentiles are descriptive and pool correlated frames.

GPU frequency was not fixed. Profiling changes latency. The virtual display supplies a nominal 60 Hz target, not measured physical presentation deadlines. We did not measure exclusive GPU ownership or hardware save/restore time.
