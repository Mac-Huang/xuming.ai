Only retained E2E case: FP16 MHA prefill → NPU at 2K

The corrected isolated operator test has exactly one validated NPU latency win: FP16 MHA prefill at W=2048. All other E2E windows, native-NPU bars, and measured NPUW-hybrid bars have been removed from this view.

Construction. 0.9464 s − 81.703 ms + 102.937 ms = 0.9677 s. The 81.703 ms term is executed IndirectSDPA + output-projection compute from three full-model GPU prefill profiles. The NPU term is 24 × 4.289 ms, the median interval union of the matching SDPA + output-projection DPU/Shave tasks from three corrected MHA traces; overlapping engines are counted once, and DMA plus residual/output-boundary work is excluded.

No E2E opportunity remains under this best-case assumption.

The compute-only bound is 2.24% slower in latency and 2.19% lower in processed-input work rate than measured GPU E2E. Real switching can only add synchronization, tensor handoff, layout/materialization, DMA, submission, and lost-fusion cost. The isolated 1.33× NPU wall-time affinity therefore does not survive the fused-compute comparison.

Scope. Qwen2.5-0.5B FP16, OpenVINO 2026.3, 2048-token prefill plus 32 fixed decode calls. Compilation is excluded. This is a compute-only upper bound, not measured heterogeneous inference; energy is intentionally not estimated because a latency decomposition cannot identify system energy.

Problems and caveats

Attribution is model-based

NPU profiling counters can overlap or be fused. The block bars apportion full-graph wall time; they are not independently runnable kernel latencies.

The oracle is not a measured hybrid

It ignores synchronization, tensor transfer, layout conversion, and recompilation boundaries. Any real scheduler must beat those costs.

Oracle energy is not claimed

Compute-time substitution cannot identify whole-system power. Energy is omitted instead of inventing a green bar.

W8A16 is not full INT8

Weights are post-training INT8 while activations remain FP16. Results should not be labeled as integer-only execution.

Scope is deliberately narrow

One Qwen2.5-0.5B shape, one NUC16 software stack, static windows, and native NPU. Affinity is not portable without remeasurement.

Fused GPU vs isolated NPU compute

GPU MHA is read from the fused full-model profile. NPU compute is a corrected single-layer trace scaled to 24 layers; the bound assumes identical NPU compute after partitioning and zero boundary cost.

Throughput is bounded and partly unstable

The maximum is only over C=1/2/4 in one process. 23 of 96 stateful concurrency points failed in the GPU/NPU runtime and are retained in the download, not silently converted to slow bars.

Method. 32 required GPU/native-NPU graph cells; 5 warm-ups, 21 wall trials, and 7 profiled trials per cell. The W=1024/2048 NPU FP16 anomaly endpoints include 27 additional profile trials across three fresh compilations. The retained E2E view contains one measured GPU baseline and one compute-only MHA-to-NPU bound at W=2048. The throughput-mode matrix has 73 successful C points, each repeated 3 times. Compilation time is excluded throughout.
