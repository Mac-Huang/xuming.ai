# Scripted memory-thrashing experiment, 2026-09-12

Holo 3.1 4B MLX 4-bit, existing pinned local model, native M5 Pro GPU. Fresh model process and two identical warmups per trial. Same closed-corpus robotics one-shot and agentic workload as preceding campaign; greedy generation, seed 42. No experiment browser/video/GPU contender. User applications remain open.

Three conditions: quiet; persistent read-only 2 GiB file mapping; persistent read-only 32 GiB mapping on a 24 GiB machine. The same single CPU loop shuffles 64 MiB blocks and reads one uint64 per 16 KiB OS page, repeatedly, without unmapping or dropping caches. File is fully written with pseudorandom bytes, fsynced, outside timing. It is not sparse. One complete sweep and 10 seconds settling precede timed inference. Large mapping is intended to force file-page eviction/reloads; actual host disk0 reads, VM page-ins, swap, compressor counters and stress progress establish whether it did. This is file-backed cache thrashing, not an anonymous dirty-memory allocation test. Logical page touches are not physical bytes transferred.

Three repetitions per condition in a Latin-square order: Q/R/T, R/T/Q, T/Q/R. Task order alternates by repetition. Exact per-call prompt hashes, token counts, final answer hashes, status, and quality checks retained. Effective throughput = generated tokens / complete task wall time. Decode throughput and TTFT reported separately. Existing cloud/9B/35B measurements remain separate, not fresh synthetic-stress baselines.

No custom thermal or swap-volume cutoffs. Native OS protections unchanged. AC power required; existing emergency available-memory thresholds retained (<768 MiB once or <1.5 GiB for >1 s), with a 600-second trial timeout and process-group cleanup. All stops remain visible. File mapping is reclaimable and read-only; no continuing dirty-file writes. Temporary 32 GiB file is removed after experiments, raw evidence kept.
