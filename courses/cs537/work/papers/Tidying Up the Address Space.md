# Tidying Up the Address Space

We learnt that paging causes internal fragmentation, but this paper points out a more important issue that often gets ignored: a mismatch between how the OS manages memory and how applications actually use it. The OS works at the page level, while applications access data at the object level. This mismatch leads to what the paper calls *hotness fragmentation*, where hot and cold data get mixed together in the same page. This is a real and impactful problem—if we could fix it, memory usage would become much more efficient and the working set would better reflect actual usage. The challenge, however, is that application behavior is dynamic and hard to predict or control. So the key question becomes: how can we reorganize memory based on how it is actually used? This is the question I had in mind while reading the paper.

To address this, Vinay proposes **address-space engineering**, which dynamically reorganizes an application’s virtual memory layout. Instead of modifying the OS, the system groups hot objects together and separates cold objects into different regions. This produces uniformly hot or cold pages, enabling existing page-level mechanisms to reclaim memory effectively.

The system, **HADES**, implements this idea using a compiler-runtime design. It tracks object accesses via lightweight metadata embedded in pointers and periodically classifies objects as hot or cold. Objects are then organized into three regions: NEW, HOT, and COLD heaps. HADES safely migrates objects between these regions using a lock-free mechanism that ensures no thread is accessing an object before it is moved. It also uses a feedback loop based on “promotion rate” (how often cold objects are accessed again) to adapt its behavior and avoid over-aggressive reclamation .

Once reorganized, the OS can reclaim entire cold pages without affecting performance. Importantly, HADES requires no OS changes—it improves memory efficiency by restructuring the input to existing systems. Experiments show up to 70% memory reduction with only 3–5% overhead .

The main limitation is that HADES only works for pointer-based data structures and cannot handle contiguous memory like arrays. Overall, the paper’s key insight is that memory inefficiency is primarily a **layout problem**, and reorganizing data at the object level can unlock the full potential of existing memory management systems.
