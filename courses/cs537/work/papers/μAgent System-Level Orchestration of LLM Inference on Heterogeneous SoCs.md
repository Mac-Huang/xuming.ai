# μAgent: System-Level Orchestration of LLM Inference on Heterogeneous SoCs

After reading the abstract of this paper, I decided to include it in my project for three main reasons. First, it extends my understanding of AI systems beyond what I learned from *Efficient Virtual Memory for Big Memory Servers* and FlexGen by focusing on system-on-chip (SoC) architectures, which represent a different type of high-performance computing system. Second, it follows an important systems design principle: identifying the real needs of workloads and designing systems specifically for those needs. This idea echoes earlier systems such as VAX/VMS, which were designed under memory constraints and heterogeneous hardware environments. Third, the paper goes beyond memory and also studies scheduling, which is another core topic in operating systems.

μAgent is a system that runs LLM inference as a continuous, multi-task workload instead of isolated requests. Unlike traditional systems that rely on a CPU–GPU setup connected by PCIe, μAgent targets modern SoCs where CPUs, integrated GPUs (iGPUs), and NPUs share the same physical memory. It focuses on agentic workloads, where user-facing (reactive) tasks and background (proactive) tasks run at the same time. This turns LLM inference into a system-level problem involving scheduling, memory management, and coordination across different hardware units.

The design is based on a key observation about LLM inference. The prefill stage is compute-bound and can run in parallel, while the decode stage is iterative and memory-bound because it repeatedly reads the KV cache. On SoCs, since all devices share memory, performance is limited more by memory bandwidth contention than by raw compute power. As a result, efficiency depends on how computation is assigned to hardware and how data movement is organized. To address this, μAgent models inference as a heterogeneous execution graph and assigns different operators to different accelerators. Compute-heavy operations are mapped to NPUs, while memory-bound decode operations are placed on the iGPU. It also separates prefill and decode into different pipelines to reduce interference. In addition, μAgent introduces flow-aware scheduling, which prioritizes latency-sensitive tasks, supports preemption, and uses batching to improve resource utilization. These mechanisms closely resemble classic operating system scheduling policies.

This work directly supports the goal of this project, which studies how operating systems evolve to support modern AI workloads. The KV cache behaves like a large working set in memory, as it is repeatedly accessed and sensitive to bandwidth limits. The scheduler in μAgent functions like an operating system managing competing processes, but at the level of LLM execution flows. Overall, μAgent shows that traditional OS concepts such as memory locality, scheduling, and resource management are still essential, but must be adapted to handle heterogeneous hardware and data-intensive AI systems.
